# Backend pipeline

Script/document builds, datums, external references, the result cache, imports, selectors, DAGMC export, OCP compatibility, and package metadata.

- TypeScript side follows `extensions/AGENTS.md` (`src/browser/`, `src/node/`, `src/common/`). Widget CSS ships via the `copy-css` build step. The Python backend in `python/` is not pip-installed; the IDE spawns it as a subprocess via `nuke-core` environment detection.
- Two authoring modes converge on one pipeline: **script mode** (a `.py` file defines a top-level `model` holding a build123d Part/Compound, CadQuery Workplane, or OCP TopoDS_Shape; `geometry_service.py` executes it in an isolated child process and hands the normalized OCP shape to `_process_shape`) and **document mode** (a `.nuke-cad` file stores parameters, datums, sketches, features; `build_document()` feeds the same `_process_shape`, so STEP, tessellation, DAGMC, and mesh artifacts are authoring-mode-agnostic).
- User scripts run in an isolated subprocess with a 120s default timeout (`--script-timeout`); `SystemExit` and unsupported model types are structured errors, not crashes. The TypeScript backend tracks spawned services in a job registry (one-hour default timeout, 1MB output tail, `cancelJob(jobId)` process-group kill, remaining jobs killed on backend stop).
- Document build (`python/feature_builder.py` in topological order over `dependsOn` edges, one accumulated body per `body` id): additive features combine into the target body, subtractive features cut, `booleanFuse`/`booleanCut`/`booleanCommon` merge tool bodies (optionally keeping tools), dress-ups apply after resolving `TopologyRef`s against the current B-rep, pattern/mirror transform stored tool shapes, holes expand from placement faces, sweep/pipe read path wires from curve results (curves build before features in `geometry_service.build_document`), loft builds positioned sections, helicalSweep derives its helix from params. Cycles are rejected with a readable member list.
- `geometry_service.py` exposes `build_document()` plus a `--from-document` CLI flag: light reference validation, curve builds, feature builder with curve results, then `_process_shape` verbatim.
- Datums: `XY`/`YZ`/`XZ`/`offset`/`face`/`threePoint`/`midplane`/`line2Point`. `offset` is an XY-plane offset along +Z. `face` resolves a planar face by fingerprint, derives a deterministic workplane from origin/normal, applies optional normal `offset`; a non-planar resolved face is a build error. `threePoint` builds the plane through three points; `midplane` sits midway between two resolved planar faces (normal face1→face2, ~1° parallelism tolerance); `line2Point` is an axis for `circularPattern.axisDatumId` only — sketch placement on it is a validation error. The frontend derives the same planes client-side (`sketch-math.ts`) so sketch entry needs no build.
- Sketches may declare `externalRefs` to predecessor-feature edges/faces. Resolved entities project into the sketch plane and reach the sketch builder as `construction` primitives — never output wires/faces. `projectedPrimitives` is reported per sketch so the viewport renders dashed construction lines. The build returns `referenceResults` (`matched`/`ambiguous`/`unmatched`) for every `TopologyRef`.
- Result cache: `build_document_partial` executes only the TS-planned dirty closure and restores clean predecessors from the `<stem>.nuke-cache.zip` sidecar (per-feature BREP blobs + tool shapes + boolean meta, `python/doc_cache.py`); opening with an empty dirty set restores everything and only tessellates. Any miss executes that feature, so an empty cache is exactly a full build. A cache-enabled full `build_document` runs that same partial builder with every feature dirty: it executes the identical feature set while priming the sidecar, so the first edit after opening restores clean predecessors. Cache IO is batched (`DocCache.batch`): one archive load, one LRU pass, and one atomic write per build, staged feature blobs are visible to later lookups in the same build, a read-only session never writes, and a build exception leaves the old archive untouched. An unchanged tess stream is not rewritten (`tessWriteSkipped`), and the doc tess blob is stored uncompressed to avoid recompressing a large JSON graph. A tess cache hit also reuses the existing canonical STEP when its `<stem>.step.key` sidecar matches the document hash, so large documents do not rewrite tens of MB on every display rebuild. Cross-body overlap verdicts are cached per body pair in the manifest, keyed by each body's content signature (the feature keys that shape it): assembly reuses verdicts for pairs whose signatures are unchanged and re-checks only pairs touching an edited body, so the O(n²) exact boolean gate is paid once per changed body rather than on every open/edit. Priming and the sidecar itself are display-build only — DAGMC/mesh exports never write it. Two self-consistent key systems, never compared across languages: TS keys back the in-session memory cache, Python content keys back the zip (sketch params, external refs, datum table, document order are key inputs on both sides). Per-feature tessellation rides the same sidecar as a doc-level `tess` blob in the manifest section, keyed by doc-hash (`store_tess`/`lookup_tess`): a hit restores shapes and skips meshing (reported via `tessCacheHit`), a miss re-tessellates. `nukeCad.resultCacheSizeMB` caps the zip before LRU eviction.
- Imports: STEP/STP/BREP files open in nuke-cad by default (higher open-handler priority than nuke-visualizer) through OCP and the same tessellation pipeline as script builds. IGES/BREP/glTF read-write, glTF write-only (this OCP has no CafReader read API), and STL export ride the same path (IGES import sews loose faces into shells first); OBJ/PLY and open-handler priorities are untouched. The `.py` open-handler priority is 50 (below the text editor's 100), so Python files open in the editor and reach the viewport via **Open With…**. STEP/IGES imports read the file length unit: unset targets adopt it, mismatches scale geometry by the exact factor (reported in the import message); BREP carries no unit metadata and is never scaled. STEP export carries per-solid labels as product names plus deterministic face colors (OCAF writer when names exist, legacy writer otherwise); STEP import restores product names and keeps one object per solid for DAGMC.
- Imported-body execution (`feature_builder._build_import_tool`) resolves `sourcePath` against the document directory (threaded through `build_document`/`build_document_partial`, assembly sub-document builds, and drawing part builds), then reads STEP/IGES/BREP through `python/exchange_reader.py` once per distinct `(path, sourceUnit, sourceFormat, maxSolids)` per build (`_BuildState.import_sources`), so 15 W7-X features share one 47 MB parse. The reader detects STEP `FileUnits`/IGES global units, uses an explicit `sourceUnit` in place of the detected unit, and scales exactly to `document.units` (native numbers when unitless); BREP has no unit metadata and is never scaled. W7-X declares millimetres but stores metre-scale numbers, so it uses `sourceUnit: 'm'` with `units: 'm'`. Selection resolves 1-based explorer indices and, when a signature is present, verifies faceCount/volume (1e-6 exact, unique 1e-3 repair) before a clear failure; placement applies intrinsic XYZ rotation, then translation. Every read streams SHA-256 and the feature fails when it differs from `params.sourceHash`, so a stale source never builds silently. `import` registers a tool shape for downstream patterns/mirrors and has no preview (Export Python emits the generic manual TODO).
- `geometry_service --inspect-import` / `inspectImportSource` is the read-only import-dialog path: the same reader returns hash/size/units/solids (index, name, faces, volume, bbox, centre) and writes no STEP/tess/DAGMC artifacts. Node `inspectImportArgs` mirrors `buildDocumentArgs`; `--source-unit`/`--target-units`/`--max-solids` mirror `InspectImportSourceRequest`.
- Native coil sweeps (`feature_builder._build_coil_sweep_tool`) sample the referenced curve wire by arc length, build rotation-minimizing frames with closed-loop holonomy correction, rotate each rectangular section by `tiltDeg` out of the tangent-normal plane plus progressive `twistDeg`, and loft through 8–720 stations with `ThruSections`. No source file or sketch is involved. The W7-X native shape study builds 10 bodies × 5 instances in ~6.5 s: 50 solids, 300 faces, 19 850 triangles, 2.58 MB tessellation, 0 warnings, total volume +0.55% vs the imported reference.
- Build-level `overlapCheck: false` rides `_BuildState.overlap_check` in `feature_builder` and is read by `assembly_builder.build_assembly`; it skips `_check_cross_body_overlap` and `_instance_overlap_warnings`, the exact boolean passes that dominate the 15-body/55-instance W7-X generator. It suppresses warnings only — geometry, selector maps, cache keys, and DAGMC export's own overlap gate are untouched.
- Design-study documents (`designStudy` present) keep the same build path but `build_document`, `build_document_partial`, and `build_assembly` reject `export_dagmc`/`export_mesh` with `DESIGN_STUDY_EXPORT_ERROR`; display builds and STEP export still work. Producers are the 4/6-module W7-X coil-count study and the native W7-X coil-shape study.
- Selectors: geometry-service extraction covers build123d labels and CadQuery Assembly names, tested against real cadquery 2.7/2.8 (TShape matching via `IsPartner`, UUID-name filtering, multi-solid Workplane handling).
- Default export gates: STEP-source imports and `.nuke-cad` opens/rebuilds skip DAGMC and FEM mesh export; the backend enforces `--no-dagmc`/`--no-mesh` on every path (including rebuilds) with opt-in `--dagmc`/`--mesh` flags.
- `dagmc_export.py` (the converter home in nuke-cad `python/`; openmc-studio's **Import from nuke-cad…** and the DAGMC editor's imprinted refacet delegate to it): surface-sense verification is a hard error (every surface must have sense 1 or 2, naming surface + volumes + imprint stage). Diagnostics in the result: `sealed=False` + warning for hole edges, `nonManifoldEdges` for incidence > 2 (imprint seams legitimately have incidence 3), `overlapCheck` from bbox + `BRepClass3d_SolidClassifier` sampling, plus additive `diagnostics` / `imprintStages` / `sealCheck`. The imprint runs staged (fragment → dedup → one capped tolerance-relaxed refragment → model-only fallback with `graveyardSkipped` → hard fail with stage log); every fallback is reported, never silent, and the model is never modified. Selector resolution is most-specific-wins (a per-cell lattice entry beats the body-level entry; disjoint selectors resolve as before). The imprint/merge pass runs in gmsh (`occ.fragment` + `removeAllDuplicates`); the optional `mat:graveyard` box is added and fragmented in gmsh too — the old OCP boolean graveyard cut is avoided because it re-duplicates coincident faces and leaks particles. Before export, `inspection_gates.py` runs warnings-only mass-property and mesh-vs-CAD deviation checks (`result["inspectionGates"]`).
- `ocp_compat.py` owns OCP 7.8/7.9 dual-flavor support. OCP 7.9 removed the `TopoDS.TopoDS.<X>_s` downcast statics (7.8 has only the `_s` names); `ensure_topo_ds_static_aliases()` re-attaches them from the non-suffixed callables so build123d 0.9.x runs on 7.9. The geometry-service child applies it eagerly before `runpy`; `install_build123d_import_hook()` registers a one-shot meta-path finder so container images activate the shim via a site-packages `.pth` line without paying OCP import cost at every startup. `BRep_Tool` keeps its `_s` statics on both flavors — do not shim it.
- Package metadata: requirements live in `src/common/packages.json` (single source of truth; never inline package lists in services/widgets). Only the `health` group is exported to TS (`CAD_HEALTH_PACKAGES`); `core`/`cad`/`dagmc` stay reference data. The `health` required set (numpy, OCP, build123d, gmsh) is what `checkCadEnvironment` treats as a working backend; the rest are `missingOptional`. Shared packages must match nuke-core's `package-registry.json`.
