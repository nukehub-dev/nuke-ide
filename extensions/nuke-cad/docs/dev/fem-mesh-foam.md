# FEM, mesh, and OpenFOAM

Region manifest with materials, gmsh/netgen meshing, the CalculiX FEM service, the OpenFOAM service, and the generic job runner.

- Region manifest volume entries may include an optional `meshSize` number for per-region refinement, plus optional `materialId`/`parentId` physical-model UUIDs (additive; the nuclear sidecar stays keyed by `material`/`name`) and a per-body `default` entry with copy propagation (`parentId` ← default's `materialId`). openmc-studio's nuke-cad import surfaces these as `materialLinks` and stamps them onto placeholder materials as copy provenance.
- A top-level `materials` block maps names to isotropic `{E, nu, rho, k, cp, alpha}` property cards plus optional `yield` strength feeding the FEM safety-factor result (documented SI units, validated, additive, version unchanged; thermal fields reserved for coupled-physics) backing FEM card resolution; `python/material_data.py` holds the versioned built-in cards keyed by the same names.
- Bodies carry an optional in-CAD material tag (`BodyDef.material`, bare name, v3-additive, set from the Feature Tree body row, read-only in the outline, undo-covered, never triggers a rebuild): `build_document`/`build_assembly`/`build_document_partial` merge tags into manifest volumes (`{selector: <label>, material: <tag>}`, explicit sidecar entries win) and persist `<stem>.regions.json` beside the document when tags contributed — that sidecar is what openmc-studio reads for `materialLinks`. DAGMC group names stay label-based (`mat:<name or selector>`); the tag travels via sidecar links, not the group name.
- Region manifest surface entries drive FEM boundary conditions in the FEM analysis panel; `name` is the selector binding loads and constraints.
- Mesh service (`python/mesh_service.py`): `engine='gmsh'` (default) and `engine='netgen'` with interface parity — per-region `meshSize` maps to `solid.maxh`, surface names become boundary-condition names, and both converge into the same meshio-based report/Exodus/INP/VTK pipeline. The netgen path imprints first: a shared gmsh load → `fragment` → `removeAllDuplicates` pass writes an imprinted BREP (a STEP round-trip re-duplicates shared faces; BREP preserves the imprint) that netgen meshes, so touching solids share one face; selector COM resolution runs in the same imprinted session. `order=2` produces real tetra10/triangle6 elements via netgen's `Mesh.SecondOrder()` with node-order remapping to the meshio/SEACAS canonical convention; `order > 2` clamps to 2 with a warning. Curved-boundary mid-nodes are netgen's best-effort projection (verified straight-edged only). The `.msh` artifact is gmsh-2.2 ASCII via meshio; a missing netgen install returns a structured error. Install netgen with the `ngsolve` pip wheel (pulls in netgen-mesher, which bundles its own OCCT 7.8.1); see `testing-e2e.md` for the conda/pip env split this forces.
- FEM service (`python/fem_service.py`): generates CalculiX `.inp` decks from gmsh `.msh` files, runs the external `ccx` executable (3600s default timeout via the `ccxTimeout` request field, output streamed to `<stem>.ccx.log` with a 1MB JSON tail), and converts FRD results to VTK. `ccx` resolves from `NUKE_CCX`, `PATH`, or an explicit request path; it is not a Python package. Material names resolve manifest-first (the manifest's `materials` block via the `materialCards` request field / `run_fem` argument), then the built-in cards in `python/material_data.py`; unknown names fail loudly, never a silent default.
- OpenFOAM service (`python/foam_service.py`): scaffolds solver-ready cases (controlDict, fvSchemes, fvSolution, transportProperties, and 0/U/p/T field files) and exports per-solid STL files from a STEP file. STL export loads STEP in-module via `STEPControl_Reader` and the `ocp_compat` TopoDS downcast — there is no `cad_conversion` dependency. Heavy OCP/build123d imports are optional; the module stays importable without them.
- Generic job runner (`python/job_service.py`): the run-layer abstraction for solver hooks — declarative working directory, command, environment, artifacts, timeout, and log capture (request schema documented in the module docstring). Timeouts and cancellation kill the whole process group. Local subprocess only today; SSH/container submit should keep the same request schema. The TypeScript backend mirrors it with a job registry and a `cancelJob(jobId)` RPC (process-group kill, one-hour default timeout, 1MB output tail, remaining jobs killed on backend stop); the FEM panel's **Stop** button uses it.
