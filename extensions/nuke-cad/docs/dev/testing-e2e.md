# Testing and e2e

Minimal-profile rule, coverage ratchet, tokamak/W7X fixtures, and environment gates.

- New Python tests must pass with only `pytest` + `numpy` installed (use `pytest.importorskip`/guarded imports for heavy deps); the full-dependency profile is exercised by the docker image test step. Heavy Python imports must be guarded so modules stay importable in the minimal profile. Tests for dependency-absence guards must force the absence (monkeypatch `sys.modules` entries to `None` or module-level `HAS_*` flags to `False`) rather than assume the ambient env lacks the dependency, so they pass in both profiles.
- Coverage split: only the pure-logic Python modules (`region_manifest.py`, `job_service.py`) are measured in the `.coveragerc` ratchet (which may only go UP — bump it when the baseline improves). The OCC/gmsh/pymoab-bound pipeline modules (`geometry_service`, `dagmc_export`, `mesh_service`, `fem_service`, `foam_service`, `ocp_compat`) are omitted because they only run in the full-dependency profile and would drag the gate down. Run `yarn test:python:cov` for the Python report (`coverage.xml`) and `yarn test:ts` for vitest.
- The e2e layer lives in `tests/e2e/` (pytest, `@pytest.mark.e2e`): real full-pipeline runs such as the pincell DAGMC test (labeled build123d pincell → STEP → imprinted h5m → real OpenMC run asserting zero lost particles). Tests are env-gated on `NUKE_TEST_PYTHON` + `OPENMC_CROSS_SECTIONS` and must skip cleanly when unset. `yarn test:python:full` runs the suite against a full-dependency Python (point `NUKE_TEST_PYTHON` at an env with openmc/h5py/vtk; set `OPENMC_CROSS_SECTIONS` for model runs). See the root `AGENTS.md` coverage/e2e bullets for the remaining gates (`NUKE_E2E_CHAIN`, `NUKE_E2E_ENDF`, `NUKE_E2E_W7X_STEP`).
- Tokamak fixture: `tests/e2e/assets/tokamak_with_divertor.nuke-cad` is authored by the GUI-path vitest driver (`src/browser/document/gui-build-tokamak.test.ts`) and exercises dense polyline sketches, revolve/pad features, circular patterns, boolean clipping, overlapping assembly bodies, and the full DAGMC export path. The Example-project JSON under `src/common/samples/` is generated from these canonical `.nuke-cad` fixtures by `scripts/copy-cad-samples.js` during the build; edit the fixture, never the generated copy. Drift, e2e, and performance coverage live in `tests/python/test_tokamak_document.py` and `tests/e2e/test_dagmc_tokamak_document_e2e.py` / `tests/e2e/test_tokamak_performance.py`. Toponaming coverage (`tests/python/test_tokamak_toponaming.py`) derives a face `TopologyRef` from the built `pf_coil_1` body via production fingerprint extraction, attaches a hole to an in-memory document copy, and asserts `matched` before and after an upstream dimension edit. The drift test compares per-body volumes (and face counts for non-spline bodies) against the authoritative STEP reference; plasma-facing spline boundaries are dense-polyline approximations checked to a relaxed 1e-3 volume tolerance.
- Only the small `.nuke-cad` sources under `tests/e2e/assets/` are fixtures: document builds write regenerable sidecars beside them (`<stem>.tess.json`, `<stem>.step` exports) that are gitignored and never committed; large reference STEPs stay developer-local via env vars.
- W7X-scale suites are opt-in: the performance measurement (`tests/e2e/test_w7x_performance.py`) via `NUKE_CAD_W7X_PERF=1` (the ×50 build takes tens of minutes; `NUKE_CAD_W7X_PERF_COUNT` overrides the count for partial runs); the demo gate (`tests/e2e/test_w7x_dagmc_e2e.py` — patterned coil document to imprinted DAGMC h5m, OpenMC fixed-source run with a zero-lost-particle assertion, plus a per-solid drift check against the developer-local reference W7-X STEP) via `NUKE_CAD_W7X_GATE=1` (the ×50 pattern fuse takes ~45 min; `NUKE_CAD_W7X_GATE_COUNT` overrides the count; `NUKE_E2E_W7X_STEP` gates the drift test — the reference STEP is never committed).
- Environment split for local testing: the dedicated `nuke` dev env (`$HOME/.conda/envs/nuke`, conda-forge OCP stack: cadquery, build123d, python-gmsh, meshio, netCDF4, vtk + pip openmc/moab/pydagmc) intentionally excludes netgen — conda netgen and conda OCP register the same OCCT types with pybind11 in one process ("type gp_Pnt is already registered!"), and the pip `ngsolve` wheel dumps its own OCCT .so files into the env's `lib/`, clobbering conda's occt. Netgen engine tests need a pip-OCP env (e.g. pip `cadquery-ocp` + pip `ngsolve`, which coexist fine).
