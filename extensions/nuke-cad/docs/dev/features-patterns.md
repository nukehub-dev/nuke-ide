# Features and patterns

Feature graph, topology references, dress-ups, patterns/mirror/lattice/multiTransform, holes/threads, sweep/pipe/loft/helix, preview, and overlap handling.

- Recompute planner: `src/common/feature-graph.ts` builds the DAG from explicit `dependsOn` edges, topologically orders it, rejects cycles with readable member lists, and plans a minimal dirty subtree via `markDirty` + `recomputePlan`. Callers clear rebuilt features with `markClean`. Suppressed features are omitted and dependents marked stale so the builder keeps last-good geometry.
- Frontend dependency rules mirror the backend: `computeDependsOn` treats loft/helicalSweep as solid producers; `CadDocumentStore.deleteSketch`'s guard and the overlay's `findConsumingFeature` honor `params.sectionSketchIds` as well as `sketchId`, mirroring backend `_feature_sketch_ids`. `_compute_implied_dependencies` additionally orders a loft after features its section sketches reference via topology.
- Topology references: `src/common/topology-refs.ts` defines fingerprint-based `TopologyRef` (`face`/`edge`) for datum faces, fillets, chamfers, drafts, shells, hole faces, patterns, sketch-on-face, and sketch external geometry. References are never raw indices. Matching/scoring lives in Python (`reference_scoring.py`, `reference_resolver.py`); TypeScript owns types and validation. Every reference resolves against the referenced predecessor feature's current B-rep with `matched`/`ambiguous`/`unmatched` status in `referenceResults` for repair affordances. Broken references carry up to 3 repair candidates with full fingerprints; the fingerprint — not the per-rebuild candidate id (`face_0007` style, re-sorted every build) — is the stored identity via `CadDocumentStore.replaceTopologyRef`. Planar-face fingerprints report the outward normal (`TopAbs_REVERSED` flips the plane axis); backend workplane derivation (`face_plane_origin_normal` / `_workplane_from_face`) and frontend UV projection (`face-picker.ts`, `sketch-math.ts`) share the convention, so off-center holes and sketch-on-face coordinates agree.
- Pad/pocket take `end` (`blind` default, `upToFirst`/`upToLast`/`upToFace`/`upToBody`/`throughAll`) with optional `twoSided` (splits `length` like `symmetric`; combining either with a non-blind end is a validation error). A missed end fails with the "does not intersect" error. `upToBody` terminates at another body's nearest/farthest ray extent along the direction. `angle` on pad/pocket is schema-accepted but unimplemented: the builder fails it explicitly instead of ignoring it. Revolve/groove take `blind` (default) or `throughAll` (profile slab fused over ±body-bbox-diagonal along the sketch-plane normal); the full UpTo set stays pad/pocket-only.
- Dress-ups (`fillet`, `chamfer`, `draft`, `shell`) operate on the body's accumulated B-rep after prior features, resolving edge/face `TopologyRef`s through the fingerprint resolver. Fillet needs `edges` + `radius`; chamfer supports symmetric (`distance`), two-distance (`distances`), and distance-angle (`distance` + `angle`); draft needs `faces`, `angle`, non-zero `pullDirection`, optional `neutralPlane` face ref; shell needs `thickness` plus optional `faces` (empty = hollow all). Dialogs enter viewport edge/face-pick modes (hover highlight, click to add). Dress-ups modify existing material, so the same-body additive overlap check is untouched.
- Patterns, mirror, holes extend the same-body chain and name a `source` solid-producing feature (`pad`/`pocket`/`revolve`/`groove`/`sweep`/`pipe`/`loft`/`helicalSweep`) on the same body, earlier in document order. The backend stores the source tool shape and transforms copies: additive sources boolean-union (overlapping instances fuse — required for coil assemblies), subtractive sources cut.
- `linearPattern` uses `count`, `spacing`, and `axis` or `axisDatumId` (mirrors circular; `line2Point` datums included, plane-datum normals accepted). `circularPattern` uses `count`, optional `angle`, and `axis` or `axisDatumId` (also accepts `line2Point`). `mirror` uses `plane` (`XY`/`YZ`/`XZ`) or `planeDatumId`. All three take optional per-instance `scale` about each instance bbox center (default 1).
- `lattice` replicates a source over a rectangular grid (`rows`×`cols`, `pitch`/`pitchY`) or hexagonal ring (`rings`, axial bound), capped at 2500 cells, with per-cell labels `<prefix>_r<row>c<col>` (odd-r) feeding `selector_map` → DAGMC groups. It fuses via the disjoint-check → parallel-fuse → sequential-fallback path, registers `tool_shapes` (pattern/mirror eligible), and rejects lattice-of-lattice.
- `multiTransform` chains two same-body pattern/mirror sources (`first`, `second`, document-ordered) over the cartesian product of their instances. Face datums behind `axisDatumId`/`planeDatumId` resolve against the referenced feature's historical shape; the hole placement face resolves against the pattern/hole body's current B-rep.
- Holes: the wizard stores one record with a face `TopologyRef` plus center `[u, v]` in the resolved face's workplane; the backend expands it into an extrude-cut with optional counterbore/countersink. Omitted `depth` = through-hole. Counterbore/countersink/counterdrill are mutually exclusive, with optional `taperAngle`, blind-only `drillPointAngle` (omitted = flat), and `thread` presets (`none`/`cosmetic`/`modeled`): `cosmetic` is stored-only, `modeled` cuts a real ISO thread (pitch/tap from `fastener_data` by diameter) as a helical cut on blind simple holes only. `defeature` deletes named faces.
- `sweep` sweeps a sketch section along a document curve (`pathCurveId`); `pipe` sweeps a circular `radius` section along a document curve. Both support `frenet`/`fixedBinormal` (non-zero `binormal` required for the latter), auto-position the section at the path start, are additive-only, and build with `BRepOffsetAPI_MakePipeShell`. `pipe` has no `sketchId`.
- Closed-spine paths (`BRep_Tool.IsClosed_s` on the spine wire) rebuild as station lofts (`_closed_spine_sweep_solid` — corner sections loft through ring-sampled station wires, circular sections through analytic circle stations) and must pass `_require_single_valid_solid`, because PipeShell periodic-seam edges carry meter-scale tolerances that degrade to bare faces on STEP round-trip. Open spines keep the PipeShell result (`_pipe_shell_result`, with a `ShapeFix_Shape` repair fallback when `MakeSolid` fails).
- `loft` joins two or more ordered sketch sections (`params.sectionSketchIds`; `FeatureDef.sketchId` unset) via `BRepOffsetAPI_ThruSections`; sections are used as positioned (no auto-positioning), must be single profiles without inner loops; `ruled=true` builds a straight skin (a ruled failure suggests `ruled=false`). Loft is additive-only. `helicalSweep` sweeps a section along an analytic helix (`axis` `X`/`Y`/`Z`, positive `startRadius`/`pitch`/`turns`, optional `leftHanded`) fitted through `curve_builder`'s interpolation path: auto-positions at the helix start, applies the `_spine_min_radius` pre-check, defaults to `fixedBinormal` locked to the axis unit vector, and takes an optional `subtractive` flag (default additive). Both are pattern/mirror-source eligible and store tool shapes.
- Sweep/pipe dialogs pick the path curve from a dropdown or a viewport curve-pick mode (click-through banner, hover highlight, right-click/Escape cancel; `resolveCurvePick` guards deleted curves). Loft picks an ordered in-dialog section list (per-row remove, up/down reorder); helicalSweep derives the path from axis/startRadius/pitch/turns with the fixed-binormal vector prefilled to the axis unit.
- Preview: every feature dialog offers a `previewEnabled` checkbox driving a debounced (~300ms) `FeaturePreviewRequest`; the widget assembles a tentative mini-document (`buildFeaturePreviewDocument`) through the normal geometry-service path and renders faces in a dedicated `cad-preview` group at ghost opacity; failures clear silently. Solid producers (pad/revolve/sweep/pipe/loft/helicalSweep/primitive) build standalone on a fresh `preview-body`; modifiers (pocket/groove/dress-up/hole/boolean) pull the referenced bodies' FULL chains to a fixpoint (cross-body booleans never replay against an empty tool body) and retarget the draft onto the real body, so fingerprints resolve against identical geometry. Blind ends, angles, and validated numerics preview; non-blind extrude ends and invalid drafts show the validator reason with no preview. Costly chains hit the backend timeout and clear per contract. `sweep-pipe.ts` stays the single home for draft validators, the section reorder helper, the closure collector, and the preview-document builder.
- Subtractive features (pocket/groove/hole) whose tool is disjoint from the body fail with "does not intersect" instead of a silent no-op.
- Same-body additive overlap: `_combine_additive` keeps the single-sketch check; overlapping additive pattern instances fuse via boolean union in `_apply_pattern_or_mirror`. When body plus every additive instance are pairwise bbox-disjoint, the union equals a flat `Compound`, so `_pattern_instances_are_disjoint` skips the fuse (touching counts as intersecting → conservative fuse; subtractive cuts always run sequentially). Otherwise one parallel `BRepAlgoAPI_Fuse` (`_pattern_parallel_fuse`: Arguments=body, Tools=instances, RunParallel + NonDestructive) runs first — ~1.5× the sequential loop on the tokamak TF pattern, slower on trivial boxes — with the sequential loop as verbatim fallback. The disjoint check compares boxes interleaved with early exit (identical verdict, touching=intersecting conservatism untouched). The W7X ×50 wall is the closed-spine sweep-station loft (~98%, accuracy-tuned) plus parallel-GFOP variance (±40% run to run); both sit outside the behavior-preserving surface and must not be optimized.
- Cross-body overlap is a warning (with overlap volume), never fatal: the B-rep build completes, `geometry_service.build_document` forwards `warnings` and `consumedBodies` (`GeometryBuildResult.warnings` / `consumedBodies`), the viewport shows a dismissible strip, and the Model Outline warnings box offers a per-pair **Fuse** auto-fix (appends `booleanFuse` merging the pair with `keepTools: false`, then rebuilds). Intentionally overlapping assemblies keep the warnings.
- Feature labels map to 1-based solid indices in `selector_map`, feeding the region-manifest/DAGMC/mesh pipeline for script builds.
