# Viewport and outline

CAD viewport chrome, tessellation worker, shading/section/measure/explode, Model Outline, Feature Tree, icons, and preferences.

- The CAD viewport is a purpose-built three.js widget (documented exception to the "reuse nuke-visualizer" rule); heavy visualization results still route to nuke-visualizer. The empty viewport shows an **Open CAD Model…** button.
- Rendering always goes through `SketchModeController.getActiveCamera()` — orthographic in sketch mode, live perspective otherwise — never a throwaway camera, or orbit/zoom/pan disconnect from the screen.
- Perspective clip planes are recomputed on every render by `clip-planes.ts` from the camera-to-target distance and the model radius (`near = max(distance·0.01, radius·1e-4)`, `far = max(distance + 3·radius, 10·radius)`). A fixed far plane silently clips any model whose bbox diagonal exceeds ~5.8k units (the tokamak demo is ~6.4k because a Move feature offsets the TF coils) and a fixed 1e-6 near/far ratio z-fights concentric shells. Never reintroduce a hard-coded far plane.
- A rebuild invalidates the displayed tessellation: the backend rewrites `<stem>.tess.json` at the same path, so `handleModelChange`'s path-equality check is bypassed with `invalidateTessellation()` when a document build starts (the previous model stays on screen until the new tessellation lands), and after opening a document.
- The bottom bar is the shared `ViewerNavBar` (nuke-essentials, one variant for CAD and native VTK viewers): ISO/top/front/right, fit, zoom in/out via `fitView`/`zoomView`/`setStandardView`; CAD-only tools (shading popover, section view, Explode slider) ride the same bar as `children`, never forked buttons. `F` fits the view when no sketch, pick mode, or text field is active. `Q` opens a transient cursor-anchored shortcut bar (sketch tools in a session, feature actions otherwise); it closes on click, Escape, or pointer-leave.
- Right-click on the canvas (no pick mode, no sketch session) opens the viewport context menu instead of the browser default: on a solid — Edit Feature… (attributed through the solid's body id to the latest non-suppressed feature writing that body; a pattern fuse resolves to its tip; disabled when nothing matches, never guessed), the three measure tools, Fit to Solid, Hide/Isolate Solid; on empty space — Fit All, Show All Solids (disabled when nothing hidden), Section View toggle, Reset Explode (disabled at 0%). Shading and section popovers share one `openPopover` slot (never both open); picking a mode, Escape, or canvas click closes it. The menu is imperative DOM (`viewport-context-menu.ts`: pure model + attribution, thin renderer; window pointerdown/Escape close), not a Theia ContextMenuRenderer.
- Key handlers are viewport-scoped: the container is focusable (`tabindex="-1"`, focused on pointerdown) and every window keydown handler early-returns unless the container holds `document.activeElement`, so Theia shortcuts work elsewhere. Tool keys (`onKeyDown`, section Escape) additionally listen in the window CAPTURE phase, because Theia's KeybindingRegistry matches from a document-capture listener and stopPropagation()s events (Escape → hide notifications ate bubble-phase tool keys whenever a notification was visible). Capture runs first; unclaimed keys still propagate. The context menu hands focus back to the container after dispatch.
- Closing the viewport widget also closes the Model Outline and Feature Tree panels (they have no model otherwise); opening a model reveals them again. Entering sketch mode on a saved sketch fits the orthographic view to the sketch bbox (`SketchModeController.fitSketchView`); fresh sketches keep the default view. `sketchEntering` covers the solver-WASM load window between **Start Sketch** and an active session (treated as sketch mode, with a "Starting sketch solver..." overlay).
- Overlays: the shared `ViewCube` orientation cube (top-right, imperative quaternion updates from `renderScene` via `ViewCubeHandle` — never React state; knob clicks snap views, and snaps needing a different up re-create the controls because OrbitControls freezes its pole at construction; hidden in sketch mode and with no model) and the shared `ViewBadge` view pill (`User view` after orbiting, `Top view` after snapping, via `onViewNameChange`). Both sit below the document toolbar (top 64px, clear of it); the status pill shares the converged `.nuke-viewer-status-line` treatment with the native VTK viewers.
- Theme colors (`viewer-core/viewport-colors.ts`): face albedo follows `--theia-foreground` on dark themes but switches to fixed steel on light editor backgrounds (near-black foreground would silhouette the model); edge lines flip white to dark slate. Changes re-color the loaded model live; initial colors re-read once after first paint so a freshly injected stylesheet is not stuck on the dark fallback (`applyThemeColors` at init + on change). The canvas backdrop follows `nukeCad.viewportBackground` (`theme`/`dark`/`light`/`gradient`, default `theme`): solid styles paint `scene.background`, `gradient` clears it for a CSS backdrop behind a transparent renderer.
- Tessellation load (`viewer-core/tess-reuse.ts` + `tess-parse.worker.ts` + `tess-parse-client.ts`, re-exported by the `widgets/cad-viewport/` shim): `.tess.json` text parses in a Web Worker (webpack-5 native `new Worker(new URL(...))`, worker imports nothing Theia) and transfers back as typed arrays — transferring the parsed object graph would cost as much main-thread time as parsing, while ArrayBuffer transfer is zero-copy into `BufferAttribute`. Worker/transport failure logs once and parses on the main thread; the feature degrades, never breaks. `buildModel` is incremental: faces pool by content-based reuse key (backend geometric fingerprint when present, else a tessellated-coordinate signature — never the process-salted `hash` or positional `solidId`/`faceId`); unchanged faces keep their `BufferGeometry` while `userData` (solid/face/body identity) re-derives from the new payload, because positional solid indices can shuffle. Edge lines and curves fully rebuild (profiled small). Stage timings log behind `localStorage['nuke-cad-profile'] = '1'`.
- Shading is a single material-state authority: `setShading(mode)` (`shaded`, `shadedWireframe`, `edgesOnly`, `xray`) plus `setGhostOpacity(v)`; pure helpers in `viewer-core/shading-modes.ts`, one `applyShading()` applies everything, and rebuilds re-apply mode and opacity. Materials are shared per shading role (body / selection / edge / curve / preview ghost), not cloned per face: selection swaps the shared reference per mesh, `applyShading` writes mode flags onto the shared materials. Edges-only hides face meshes and disables face/solid picking (hint pill); x-ray ghosts faces at ghost opacity with opaque edges.
- Section plane (`setSection({axis, flip, fraction} | undefined)`, pure math in `viewer-core/section-plane.ts`) clips faces and edge lines via `renderer.localClippingEnabled`; visual-only, slider-driven over the tessellation bbox, exits on button/Escape, survives rebuilds through `applyShading()`.
- Measure tool (pure logic in `viewer-core/measure-tool.ts`), launched from the document toolbar Inspect group or sketch toolbar, with a mode selector in the Measurements popover: point-to-point **distance** (raycast surface points in 3D, snap-aware sketch-plane points in sketch mode), three-click **angle** A→vertex B→C with overlay segments BA/BC and the label at B, and edge **radius** (model3d-only via `edge-picker.ts`: mean polyline distance to the fingerprint center when present, else a Kasa least-squares circle fit in the best-fit plane from `radius-fit.ts`, rejecting non-circular edges with a status warning). Angle/radius capture is model3d-only; sketch mode is always distance. All kinds render as overlay lines/spheres with imperative HTML labels projected in `renderScene`; overlay updates run BEFORE `renderer.render` (with a fresh `cam.updateMatrixWorld()`), because render-on-demand has no next frame to fix a stale paint.
- Measurements are viewport state by default and clear on rebuild or sketch exit. Pinning a 3D measurement persists it to the additive `measurements: SavedMeasurement[]` document block (`{id, kind: distance|angle|radius, points, label, createdAt}`, model units, v3 with no migration — absent = none) via `CadDocumentStore` `addMeasurement`/`removeMeasurement` (validated, undo-covered, dirty-flagged, never rebuild-scheduled); pinned entries re-render after rebuilds via `toSavedMeasurement` / `fromSavedMeasurement` / `restoreSavedMeasurements` (radius round-trips as center + rim point). The backend never reads the block: codegen and result-cache keys ignore it (asserted in `cad-document-store-measurements.test.ts`).
- Explode view (navigation cluster) is per-solid viewport-only state: `viewer-core/explode-view.ts` plans solidId → offset as `normalize(centroid − bboxCenter) · diagonal · factor · EXPLODE_MAX_SPAN (0.35)` from vertex-averaged centroids (the cap keeps 100% explode framed); the widget applies it as mesh/edge-line `.position` transforms after every `buildModel` (transform only — reuse pool, geometry, and picking untouched; raycasts use world matrices; curve lines stay pinned at the origin). Factor 0 is assembled; the factor resets on reload/rebuild like measurements, and measurements stay world-anchored while displaced (hint reads `Explode N% — F to refit`).
- Selection and visibility: `fitView` frames the selected solid when `currentSelection.solidId` is set; `.` and double-click-on-solid also fit; `Tab` toggles sketch mode (guarded against pick modes, dialogs, text fields). `CadSelection.solidIds` multi-selects (Ctrl/Cmd in the outline, or a tree body/feature click mapping to all body solids); `solidId` stays primary (properties panel, fit). The outline's hide/isolate actions publish a hidden-solids set via `NukeCadStateManager.setHiddenSolidIds` — viewport state, never document state — applied in `applyShading` (faces and edges) and excluded from every picking path (`pickableMeshes()` / `pickableEdgeLines()`; three.js raycasts invisible objects, so the pool filters explicitly). Document curves hide exactly when every body consuming them as a sweep/pipe path is fully hidden (`curve-visibility.ts`, same `applyShading` funnel, `pickableCurveLines()`; unreferenced curves always stay). The set clears on `setModel` because positional solid indices can shuffle.
- Model Outline (`src/browser/widgets/outline-panel/`, `nuke-cad-outline-panel-widget`, "Model Outline"): read-only manifest volumes/surfaces list (plus ASSEMBLIES per-instance rows for assemblies) — no manifest editing UI. Picking syncs both ways through `NukeCadStateManager`: row click highlights the whole solid (Ctrl/Cmd toggles multi-selection, `outline-interactions.ts`); viewport picks select, scroll to, and expand the row. Hover actions **Hide** (toggle its solids) / **Isolate** (hide all others); a **Show all** header button appears while hidden; hidden rows render dimmed with an eye-closed marker. Opened via `nuke.cad.openOutlinePanel` (right shell) or the Nuke Tools sidebar (`CAD Studio → Geometry`). From shared per-solid summaries (`SolidSummary` published after tessellation parse, `solid-summaries.ts`): a **Properties** section (volume, area, bbox size, center of mass, face/edge/triangle counts in model units, pin toggle) and a sortable **Table view** (Solid/Body label/Volume/Area/Faces/Tris, same selection sync incl. Ctrl/Cmd multi-select). Missing data renders as em-dashes for older payloads. The **Parameters** section (`.nuke-cad` only) is the parameter spreadsheet: sortable `{name, value, unit, used-by}` rows with edit-in-place (numbers or `expression.ts` expressions over other parameters, inline validator reasons, never commits invalid input), an add row, and a referenced-guard delete; `used-by` resolves via `CadDocumentStore` (`collectParameterUsages`: dimension bindings, parameter-valued constraint fields, curve-expression idents, plus the `planDirtyRebuild` feature closure); every edit rides the normal store path. Its **BOM** button exports `{instance/body, label, material, volume}` CSV from `SolidSummary` data (`param-table.ts`). The **Build warnings** box parses overlap warnings (`parseOverlapWarning`) and, for open `.nuke-cad` documents containing both bodies, renders a per-warning **Fuse** button (appends `booleanFuse` via `buildFuseFeature`: target tip + tool tip as `dependsOn`, `keepTools: false`, then rebuilds); script/STEP models get no button. Non-fatal build warnings also render as a collapsible viewport strip (`N build warning(s)`, reset to collapsed per build).
- Geometry-service inspection properties: every tessellation solid entry optionally carries `volume`, `area`, `bbox.min/max`, `centerOfMass` (OCP `GProp_GProps` + `BRepBndLib` in `_process_shape`'s `_solid_properties`). Additive and best-effort: on failure the key is omitted and the build never breaks; consumers treat it as optional.
- Feature Tree (`src/browser/widgets/feature-tree/`, `nuke-cad-feature-tree-widget`, "Feature Tree"): bodies, datums, sketches, features, curves in document order (plus Instances/Mates for assemblies) with selection, suppression toggle, edit, delete, build-status markers, and `ambiguous`/`unmatched` badges from the last rebuild. Body/feature clicks highlight the body's tessellated solids via `NukeCadStateManager` (bodyId mapped through `SolidSummary`; no-op with no built solids). Boolean features show target/tool bodies inline. The **CURVES** section offers inline rename/delete plus a source-recipe dialog (`curve-dialog.tsx`); selecting a curve highlights its viewport polyline. Inline rename for bodies/features/curves, up/down reorder with dependency-precedence validation, cascade-delete prompts when later pattern/mirror features use the target as `source`, and a reference-repair popover (fingerprint-compared candidates; may stay unmatched for manual repair).
- Icons: `src/browser/widgets/cad-viewport/cad-icons.css` mask-based `codicon-nuke-cad-<name>` classes (16×16, `currentColor`, Theia file-icon technique) for toolbar buttons, tree rows, widget `title.iconClass`, and the Nuke Tools sidebar (registry `icon` takes bare `nuke-cad-<name>` via `codicon()`). New glyphs follow the documented 16px grid in the CSS header; never substitute a generic codicon for a panel/feature that already has a dedicated icon.
- Preferences (`src/browser/nuke-cad-preferences.ts`): `nukeCad.facetingTolerance` (default 0.001, exclusiveMinimum 0) is the export-quality default (script builds and builds with DAGMC/FEM export enabled; explicit per-call tolerance wins; applies to subsequent builds only; deliberately separate from openmc-studio's tolerance — nuke-cad cannot depend on openmc-studio). Viewport-only builds use coarser `nukeCad.displayFacetingTolerance` (default 0.01) for fast opens; `nukeCad.maxDisplayTriangles` (default 2 000 000) warns over budget. DAGMC/FEM tolerances are unaffected by display settings. `nukeCad.viewportBackground` (`theme`/`dark`/`light`/`gradient`, default `theme`) picks the canvas backdrop. `nukeCad.navigationStyle` (`orbit`/`solidworks`/`tinkercad`/`touchpad`, default `orbit`) remaps OrbitControls button tables (`viewer-core/navigation-styles.ts`, re-applied after every controls re-creation); right-click menus work in every style, modifier-key styles stay out. `nukeCad.rebuildOnEdit` (`auto`/`manual`, default `auto`) gates edit rebuilds: `manual` marks the model stale (banner + Rebuild button) instead of rebuilding; opening always builds, plain Save never builds. `nukeCad.resultCacheSizeMB` (default 1024, minimum 1) caps the `<stem>.nuke-cache.zip` sidecar before LRU eviction (threaded as `sizeCapMB` on every partial call).
