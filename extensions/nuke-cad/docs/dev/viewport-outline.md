# Viewport and outline

CAD viewport chrome, tessellation worker, shading/section/measure/explode, world-origin axes, named views, Model Outline, Feature Tree, icons, and preferences.

- The CAD viewport is a purpose-built three.js widget (documented exception to the "reuse nuke-visualizer" rule); heavy visualization results still route to nuke-visualizer. The no-document viewport shows an **Open CAD Model…** empty state; an empty document shows a centered **Start a model** launcher (`.cad-viewport-document-empty`, not `NukeEmptyState`) with a primary **Create Sketch** tile and compact **Open CAD Model…** / **Import CAD…** / **Import CAD as Body…** rows while the ribbon stays mounted. The launcher uses container queries: two columns when its content box is wide enough, one column below 480 px, and a labels-only compact mode below 260 px.
- Rendering always goes through `SketchModeController.getActiveCamera()` — orthographic in sketch mode, live perspective otherwise — never a throwaway camera, or orbit/zoom/pan disconnect from the screen.
- Perspective clip planes are recomputed on every render by `clip-planes.ts` from the camera-to-target distance and the model radius (`near = max(distance·0.01, radius·1e-4)`, `far = max(distance + 3·radius, 10·radius)`). A fixed far plane silently clips any model whose bbox diagonal exceeds ~5.8k units (the tokamak demo is ~6.4k because a Move feature offsets the TF coils) and a fixed 1e-6 near/far ratio z-fights concentric shells. Never reintroduce a hard-coded far plane.
- A rebuild invalidates the displayed tessellation: the backend rewrites `<stem>.tess.json` at the same path, so `handleModelChange`'s path-equality check is bypassed with `invalidateTessellation()` when a document build starts (the previous model stays on screen until the new tessellation lands), and after opening a document.
- The bottom bar is the shared `ViewerNavBar` (nuke-essentials, one variant for CAD and native VTK viewers): ISO/top/front/right, fit, zoom in/out via `fitView`/`zoomView`/`setStandardView`; CAD-only tools (shading popover, section view, Explode slider) ride the same bar as `children`, never forked buttons. `F` fits the view when no sketch, pick mode, or text field is active. `Q` opens a transient cursor-anchored shortcut bar (sketch tools in a session, feature actions otherwise); it closes on click, Escape, or pointer-leave.
- Document toolbar (`DocumentModeToolbar` in `cad-sketch-overlay.tsx`) is one non-wrapping chrome row beside the document info/units block, built from seven `role="group"` `NukeRibbonSection`s (nuke-essentials): Document, Sketch, Additive, Boolean, Dress-up, Pattern, Inspect. Promotion is data in `CAD_RIBBON_GROUPS` (`src/browser/cad-command-registry.ts`): Document 5 (Export as Python in the caret menu), Sketch all present (`New Sketch` + `Edit Selected Sketch`), Additive 3 (Groove/Loft/Sweep/Pipe/Helical Sweep in the menu), Boolean 3, Dress-up 3 (Draft/Move in the menu), Pattern 3 (Lattice/Hole in the menu), Inspect 4 (Measure, Measurements, Feature Tree, Model Outline inline). Each caption row carries a caret for the section's full command list; the menu portals to `document.body`, positions before paint, closes on Escape/outside click, returns focus on Escape, and keeps disabled items disabled. Density comes from a `ResizeObserver` on the toolbar via `selectRibbonDensity`: ≥ 1700 px `tiles` (24 px icon over a 12 px `shortLabel`, 64 px tile; the full label carries shortcuts and stays in the tooltip/menu), 930–1699 `icons` (26×26 buttons), < 930 `menus` (one `caption ▾` button per section), with 40 px hysteresis on every boundary. An overflow check (`scrollWidth > clientWidth`) also forces `menus` instead of clipping a dense row. At ≤ 900 px the document info/search occupy the first row and the ribbon wraps to a full-width second row; `menus` captions use compact short labels (`Doc`, `Sketch`, `Add`, `Bool`, `Dress`, `Pattern`, `Inspect`) and tighter section spacing so they never ellipsize. The measured bar height feeds `--nuke-cad-toolbar-bottom`, which keeps `ViewCube`/`ViewBadge` below the chrome in every density. During sketch setup the bar stays mounted with **New Sketch** pressed (**Edit Selected Sketch** when editing); the `.cad-sketch-datum-picker` task panel (role `dialog`, 260 px) is anchored top-right below the 68 px ViewCube slot so it never covers the cube.
- Viewport banners (`.cad-viewport-banners`) anchor top-left with `align-items: flex-start` and deliberately no `z-index` (no stacking context), so the warning strip/popover can rise above the z-index-20 sketch overlay while the error banner (no `z-index`) stays behind the sketch chrome. Build warnings use a compact badge: `width: fit-content`, `max-width: min(260px, calc(100% - 16px))`, a single-line header (icon, `N build warnings` toggle, dismiss X), and `z-index: 30`. In document mode `.cad-viewport:has(.cad-document-toolbar) .cad-viewport-banners` moves the stack to `top: calc(var(--nuke-cad-toolbar-bottom, 64px) + 4px)` so the z-index-20 toolbar can never hide it; sketch mode keeps `top: 8px`, where a ≤260 px badge ends before the centered constraint bar and Finish pill. Expanding the list renders `.cad-viewport-warning-popover` (absolutely positioned `top: calc(100% + 6px); left: 0`, 340 px wide, 180 px tall cap with its own scroll, widget background/border/shadow, `z-index: 30`) instead of growing the strip; it closes on the toggle, outside pointerdown, or Escape (window listeners attached only while open). The error banner keeps `width: min(100%, 720px)`.
- Ribbon customization is user state, not document state. `nukeCad.ribbonLabels` (boolean, default `true`) forces compact `icons` rendering when the measured density would be `tiles`; width-selected `icons`/`menus` are unchanged, and sections still collapse to menus when narrow. `nukeCad.ribbonPins` (unique string array, default empty) becomes each group's `promotedIds`; `NukeRibbonSection` uses `splitRibbonByPromotion` (`nuke-ribbon-model.ts`) to render the first `promoted` defaults plus pinned ids in group order, ignoring unknown ids, deduping, and capping inline buttons at 8 (`RIBBON_INLINE_PIN_CAP`). The caret menu lists every item, inline ones included; each row is a wrapper div with the action button plus a separate pin/unpin icon button (`aria-label` `Pin to toolbar`/`Unpin from toolbar`, never nested inside the action button) whose click neither closes the menu nor runs the command. `CadViewportWidget` reads both keys through the preferences proxy, subscribes to `onPreferenceChanged` (same filtered subscription as the decimal preferences) and re-renders; the toggle writes the deduped array of `CAD_COMMAND_IDS` with `PreferenceScope.User`.
- CAD commands come from one pure table (`src/browser/cad-command-registry.ts`, no React/Theia): `CAD_RIBBON_GROUPS` fixes the seven section captions/promoted counts, and `buildCadCommands(context, handlers)` returns the ordered `CadCommandSpec`s (`id`, `label`, `shortLabel`, `icon`, `group`, `shortcut`, `isEnabled(context)`, `disabledReason(context)`, `run()`). The ribbon and command search both consume that result; add or change a command there, never in the toolbar. Disabled specs carry an actionable reason (e.g. `Select a sketch first.`), rendered in the disabled tooltip (`label — reason`), the ribbon menu's second line, and the search row. Active states stay host-owned because they describe a transient UI mode, not availability.
- Command search lives at the right end of the toolbar actions row: a 26×26 `codicon-search` trigger (`aria-label="Search CAD commands"`, tooltip `Search CAD commands (/)`) that stays visible in tiles/icons/menus density and never wraps the ribbon. `CadCommandSearch` (`cad-command-search.tsx`, pure filter in `cad-command-search-model.ts`) is rendered inside the toolbar root (never portaled) and absolutely positioned under it (`top: calc(100% + 6px); right: 8px`; 340 px wide, 320 px tall cap). `DocumentModeToolbar` maps the shared `buildCadCommands` specs (promoted buttons plus caret-menu tails) into `{id, label, shortLabel, icon, disabled, disabledReason, group, onClick}` rows; the filter is a case-insensitive substring over label + shortLabel + group, capped at 12 rows, with disabled rows listed but inert and their reason in a muted `.cad-command-search-reason` line. Keyboard: ArrowUp/ArrowDown move the active row, Enter runs it (or the first match), Escape/Tab close; the window-CAPTURE handler `stopPropagation()`s so the viewport and Theia never also react, outside pointerdown closes, and each open resets the query and focuses the `NukeSearchInput`. `DocumentModeToolbar`'s document-mode `/` listener runs on window bubble phase, requires the event target inside this `.cad-viewport` and outside inputs/textareas/selects/contenteditable, and is blocked by `searchShortcutBlocked` (sketch setup/task panel, feature dialog, face/dress-up/hole/curve pick, measure, shortcut bar); the toolbar only mounts outside sketch sessions. The viewport's document-mode Escape selection-clear guard treats `.cad-command-search-popover` as a transient overlay, so closing search never drops the selection.
- Right-click on the canvas (no pick mode, no sketch session) opens the viewport context menu instead of the browser default: on a solid — Edit Feature… (attributed through the solid's body id to the latest non-suppressed feature writing that body; a pattern fuse resolves to its tip; disabled with the native-title reason `No feature writes this body.` when nothing matches, never guessed), Find in Feature Tree (selects that feature row and reveals the panel; omitted when no feature owns the body), Appearance… (opens the per-body display color/opacity dialog; shown only when the hit carries a body id), Select Other… (shown only while the right-click ray crosses more than one distinct face; hint `Alt+click`), the three measure tools, Fit to Solid, Hide/Isolate Solid (plus bulk Hide/Isolate Selected for a multi-selection), Clear Selection (Esc, only while a selection exists); on empty space — Clear Selection first when a selection exists, then Fit All, Show All Solids (disabled when nothing hidden), Section View toggle, Reset Explode (disabled at 0%). Items carry right-aligned hints only for real bindings (`F` on Fit to Solid, `Alt+click` on Select Other…, `Esc` on Clear Selection; Fit All has none because F fits the selection), mirrored by `aria-keyshortcuts`. Escape clears a document-mode selection (never while a pick/measure/sketch/section tool owns the key); an open menu consumes the first Escape itself. Shading and section popovers share one `openPopover` slot (never both open); picking a mode, Escape, or canvas click closes it. The menu is imperative DOM (`viewport-context-menu.ts`: pure model + attribution, thin renderer; window pointerdown/Escape close), not a Theia ContextMenuRenderer.
- Select Other disambiguates overlapping picks. `raycastFaceCandidates()` (`face-picker.ts`) maps one raycast's intersections to `{solidId, faceId, bodyId?, distance, point?, mesh}`, drops invalid `userData`, dedupes `solidId:faceId` keeping the nearest hit (a shell entered and exited is one face), orders by distance, and caps at 16; `dedupeFaceCandidates` is the pure, unit-tested half. The widget keeps the right-click candidate list in a local, passes `selectOtherCount` to the menu model, and dispatches into `select-other-menu.ts`: `buildSelectOtherRows` resolves `document.bodies` labels (`label ?? name ?? id`, else `Solid <solidId>`) and formats `face <faceId>` plus `formatMeasureDistance(distance, decimals)` with the live length precision; `openSelectOtherMenu` renders the anchored, clamped popover (outside pointerdown/Escape close, pick then container focus) and `Select Other…` appears only when the count exceeds one. Alt+click in normal document mode — no sketch session and no measure, face, dress-up, hole, curve, dimension, or connector pick mode — cycles the same candidate list from the current `{solidId, faceId}` selection and wraps at the end; one/zero candidates fall through to the plain click, and Ctrl/Cmd additive picks are unchanged whenever Alt is not held. Context menu and popover close on every rebuild (`buildModel`) and unmount because their candidates reference meshes that are disposed.
- Dress-up edge picks can expand to a tangent chain (`tangent-edge-chain.ts`, opt-in via the fillet/chamfer **Tangent chain** checkbox, default off). The pure walker treats each edge line's first/last points as graph vertices (squared distance < 1e-8) and walks outward from both seed endpoints through unused edges whose direction _away_ from the shared vertex is nearly opposite the current edge's (`dot < -cos(15°)`), capped at 256 edges including the seed. Order is seed, forward chain, then backward chain; a closed loop stops when the seed would repeat, and degenerate/incomplete edges are skipped. Only lines carrying the hit's `solidId` feed the walker, so chains never cross solids; face picks (draft neutral plane, shell faces) ignore the flag. Every chained edge becomes its own fingerprint `TopologyRef` (deduped by producing feature + fingerprint, missing fingerprints skipped with one warning) and the dialog callback fires once per ref, appending each to its list; with the option off the single-edge path is byte-identical.
- Key handlers are viewport-scoped: the container is focusable (`tabindex="-1"`, focused on pointerdown) and every window keydown handler early-returns unless the container holds `document.activeElement`, so Theia shortcuts work elsewhere. Tool keys (`onKeyDown`, section Escape) additionally listen in the window CAPTURE phase, because Theia's KeybindingRegistry matches from a document-capture listener and stopPropagation()s events (Escape → hide notifications ate bubble-phase tool keys whenever a notification was visible). Capture runs first; unclaimed keys still propagate. The context menu hands focus back to the container after dispatch.
- Closing the viewport widget also closes the Model Outline and Feature Tree panels (they have no model otherwise); opening a model reveals them again. Entering sketch mode on a saved sketch fits the orthographic view to the sketch bbox (`SketchModeController.fitSketchView`); fresh sketches keep the default view. `sketchEntering` covers the solver-WASM load window between **Start Sketch** and an active session (treated as sketch mode, with a "Starting sketch solver..." overlay).
- Reopening the viewport restores the active model on `onAfterAttach`: if the state manager still has a model with a tessellation path, that tessellation is reloaded without a backend spawn; otherwise a saved document rebuilds through the cached open path. The restore overlay clears when the tessellation lands, so a close/reopen never shows the empty-document card over a still-open document. The same hook re-reveals the Model Outline and Feature Tree panel widgets; the Inspect ribbon and command search also carry explicit **Feature Tree** / **Model Outline** actions.
- The New Document command marks the flow before attaching a fresh viewport (`prepareForNewDocument`), so the attach-time restore cannot rebuild the previous document behind the template picker. Choosing a template clears `tessData`, the state-manager model, pending build results, and queued rebuilds before installing the new document, so old geometry/lists never flash over the new empty document.
- Overlays: the shared `ViewCube` orientation cube (top-right, imperative quaternion updates from `renderScene` via `ViewCubeHandle` — never React state; knob clicks snap views, and snaps needing a different up re-create the controls because OrbitControls freezes its pole at construction; hidden in sketch mode and with no model) and the shared `ViewBadge` view pill (`User view` after orbiting, `Top view` after snapping, via `onViewNameChange`). Both sit below the document toolbar (top follows the measured `--nuke-cad-toolbar-bottom` published by the bar, 64px fallback); the status pill shares the converged `.nuke-viewer-status-line` treatment with the native VTK viewers.
- Assembly panel (`assembly-instance-list.tsx`) is a floating card anchored at `top: 104px; left: 8px` under the toolbar. `useDraggablePanel` with `headerRegionTarget('.cad-assembly-header')` makes only the header a drag/reset handle (buttons excluded, double-click/right-click reset, existing clamp keeps the card reachable), while local `collapsed` state toggles a chevron (`aria-expanded`, `aria-label` Collapse/Expand assembly panel) and keeps the dragged position; collapsed renders the header only. The header carries the assembly icon, title, `N instances` badge, and a DOF readout only when instances exist. The labelled part input (`aria-label="Assembly part"`, placeholder `./part.nuke-cad, .step, or body:<id>`) accepts a `.nuke-cad` path, STEP/IGES/BREP path, or same-document `body:<id>`; Enter submits, the primary Instance button is disabled until the trimmed value is non-empty, and Mate… shares the right-aligned action row only when instances exist. Instance select/rename/ground/delete callbacks are unchanged. Hover help (header hint, DOF, grounded badge, instance/part labels, ground/delete actions, part input) uses the shared `Tooltip`/`useTooltip`, never native `title` attributes, so it follows the NukeIDE theme and viewport-edge flipping.
- Theme colors (`viewer-core/viewport-colors.ts`): face albedo follows `--theia-foreground` on dark themes but switches to fixed steel on light editor backgrounds (near-black foreground would silhouette the model); edge lines flip white to dark slate. Changes re-color the loaded model live; initial colors re-read once after first paint so a freshly injected stylesheet is not stuck on the dark fallback (`applyThemeColors` at init + on change). The canvas backdrop follows `nukeCad.viewportBackground` (`theme`/`dark`/`light`/`gradient`, default `theme`): solid styles paint `scene.background`, `gradient` clears it for a CSS backdrop behind a transparent renderer.
- Tessellation load (`viewer-core/tess-reuse.ts` + `tess-parse.worker.ts` + `tess-parse-client.ts`, re-exported by the `widgets/cad-viewport/` shim): `.tess.json` text parses in a Web Worker (webpack-5 native `new Worker(new URL(...))`, worker imports nothing Theia) and transfers back as typed arrays — transferring the parsed object graph would cost as much main-thread time as parsing, while ArrayBuffer transfer is zero-copy into `BufferAttribute`. Worker/transport failure logs once and parses on the main thread; the feature degrades, never breaks. `buildModel` is incremental: faces pool by content-based reuse key (backend geometric fingerprint when present, else a tessellated-coordinate signature — never the process-salted `hash` or positional `solidId`/`faceId`); unchanged faces keep their `BufferGeometry` while `userData` (solid/face/body identity) re-derives from the new payload, because positional solid indices can shuffle. Edge lines and curves fully rebuild (profiled small). Stage timings log behind `localStorage['nuke-cad-profile'] = '1'`.
- Shading is a single material-state authority: `setShading(mode)` (`shaded`, `shadedWireframe`, `edgesOnly`, `xray`) plus `setGhostOpacity(v)`; pure helpers in `viewer-core/shading-modes.ts`, one `applyShading()` applies everything, and rebuilds re-apply mode and opacity. Materials are shared per shading role (body / selection / edge / curve / preview ghost), not cloned per face: selection swaps the shared reference per mesh, `applyShading` writes mode flags onto the shared materials. Edges-only hides face meshes and disables face/solid picking (hint pill); x-ray ghosts faces at ghost opacity with opaque edges.
- Per-body appearance overrides (`BodyDef.appearance`, resolved by the pure `body-appearance.ts`): `resolveBodyAppearance` exposes the stored color/opacity block for the dialog, `resolveBodyMaterialColor` maps a body's `material` tag through the shared `materialColor` palette when `nukeCad.colorByMaterial` is on, and `resolveBodyDisplayAppearance` fixes the viewport precedence (`appearance.color` > material color > theme base) while keeping `appearance.opacity` independent. `initViewport` keeps a `Map<bodyId, {material, color?, opacity?}>` of cloned `bodyMaterial` instances for bodies with a fixed color or opacity only (untagged bodies and coloring off stay on the shared materials), rebuilt by `syncBodyAppearances()` from `documentStore.document.bodies` after every `buildModel`, on `documentStore.onChange`, and from `ViewportApi.setColorByMaterial` when the preference changes (disposed on replace/remove, model reset, and unmount). `applyHighlight` picks `isSelected ? highlightMaterial : (appearanceMaterial(bodyId) ?? bodyMaterial)`, so selection keeps the shared highlight. Shading precedence: `shaded` uses the override opacity (`transparent` + `depthWrite:false` when < 1); `xray` wins with the ghost opacity; `shadedWireframe`/`edgesOnly` keep full opacity. Theme recolor keeps fixed colors fixed — explicit appearance colors and material palette colors alike; opacity-only overrides take the fresh theme base color. Rebuild scheduling never observes these commits. The dialog's preset library is user state, never document state: `nukeCad.appearancePresets` is normalized by `normalizeAppearancePresets` (trim/dedupe names, lower-case hex, clamp opacity, drop invalid entries), saved/deleted through `PreferenceService.set(..., PreferenceScope.User)`, and only fills the dialog draft. Applying to a multi-body viewport selection maps `CadSelection.solidIds` through `SolidSummary.bodyId` and calls `CadDocumentStore.setBodiesAppearance(ids, appearance)` — deduped ids, all ids validated, one commit so the whole batch is a single undo entry; the single-body `setBodyAppearance` delegates to it. Remove override uses the same batch path when the checkbox is on.
- Section plane (`setSection({axis, flip, fraction} | undefined)`, pure math in `viewer-core/section-plane.ts`) clips faces and edge lines via `renderer.localClippingEnabled`; visual-only, slider-driven over the tessellation bbox, exits on button/Escape, survives rebuilds through `applyShading()`.
- World-origin axes (`origin-axes`) are display-only: `initViewport` adds one scene-level `THREE.Group` with three `THREE.Line`s from `(0,0,0)` along +X/+Y/+Z (`#e05252`/`#4caf50`/`#3b82f6`), each with a `LineBasicMaterial` (`depthTest: false`, `transparent: true`, opacity 0.9, `toneMapped: false`), `renderOrder` 990, and frustum culling off. `buildModel` sets their length to `max(lastDiag * 0.08, 1)` after the new bbox diagonal (empty/reset model: 5). `ViewportApi.setOriginAxes({enabled,x,y,z})` stores the master `nukeCad.showOriginAxes` flag and flips each line's visibility from `nukeCad.showOriginX`/`showOriginY`/`showOriginZ` (all default `true`); the component applies preference changes through the existing `onPreferenceChanged` subscription and a prop effect without re-initializing the scene, and init applies the initial values. `renderScene` hides the whole group unless the master is on, a tessellation is loaded (`currentTessData !== undefined && meshes.length > 0` — so the welcome card, an empty document, and `updateModel(undefined)` show no axes), and `SketchModeController.isActive` is false and the prop effect has not marked sketch setup/entering as suppressed; both restore on exit. The per-axis flags only matter while the master is on. Never document state: no rebuild, codegen, manifest, or export reads it; line geometries and materials dispose in cleanup.
- Measure tool (pure logic in `viewer-core/measure-tool.ts`), launched from the document toolbar Inspect group or sketch toolbar, with a mode selector in the Measurements popover: point-to-point **distance** (raycast surface points in 3D, snap-aware sketch-plane points in sketch mode), three-click **angle** A→vertex B→C with overlay segments BA/BC and the label at B, and edge **radius** (model3d-only via `edge-picker.ts`: mean polyline distance to the fingerprint center when present, else a Kasa least-squares circle fit in the best-fit plane from `radius-fit.ts`, rejecting non-circular edges with a status warning). Angle/radius capture is model3d-only; sketch mode is always distance. All kinds render as overlay lines/spheres with imperative HTML labels projected in `renderScene`; overlay updates run BEFORE `renderer.render` (with a fresh `cam.updateMatrixWorld()`), because render-on-demand has no next frame to fix a stale paint. Display precision comes from `nukeCad.lengthDecimals`/`nukeCad.angleDecimals` (defaults 2/1) through `formatMeasureDistance(value, decimals)`, `formatMeasureAngle(degrees, decimals)`, `formatMeasureRadius(radius, decimals)`, and `formatMeasurementValue(measurement, {length, angle})`; `initViewport` keeps one mutable decimals object that every committed label, live pending label, radius label, and popover row reads, and `ViewportApi.setMeasurementDecimals` refreshes the cache plus re-renders when the React effect sees a preference change. The document-mode Measurements popover (`.cad-viewport-measure-popover`) opens below the document bar via `top: calc(var(--nuke-cad-toolbar-bottom, 64px) + 4px)` (the sketch popover keeps its fixed offset), and its close/remove/Clear All buttons set `color: var(--theia-secondaryButton-foreground)` explicitly so light-theme panels never inherit the white primary-button foreground.
- Measurements are viewport state by default and clear on rebuild or sketch exit. Pinning a 3D measurement persists it to the additive `measurements: SavedMeasurement[]` document block (`{id, kind: distance|angle|radius, points, label, createdAt}`, model units, v3 with no migration — absent = none) via `CadDocumentStore` `addMeasurement`/`removeMeasurement` (validated, undo-covered, dirty-flagged, never rebuild-scheduled); pinned entries re-render after rebuilds via `toSavedMeasurement` / `fromSavedMeasurement` / `restoreSavedMeasurements` (radius round-trips as center + rim point). The backend never reads the block: codegen and result-cache keys ignore it (asserted in `cad-document-store-measurements.test.ts`).
- Named views persist camera poses to the additive `views: SavedNamedView[]` block (`{id, name, position, target, up, createdAt}`, world-space tuples, v3 with no migration — absent = none) via `CadDocumentStore` `addNamedView`/`removeNamedView` (validated, unique trimmed names, 32-entry cap, undo-covered, dirty-flagged, never rebuild-scheduled). The mounted scene publishes `getCameraState`/`setCameraState` through the `onCameraApiReady` component prop; `CadViewportWidget` holds the pair for `saveNamedView`/`restoreNamedView`. Restore copies position/target without clamping (non-finite vectors ignored; `up` normalized), re-creates OrbitControls when `up` differs, leaves the badge at `User view`, and never clamps distance. The backend never reads the block (asserted in `cad-document-store-views.test.ts`).
- Explode view (navigation cluster) is viewport-only state: `viewer-core/explode-view.ts` plans offsets per explode unit (assembly instance, else body, else solid) from vertex-averaged centroids. Off-center units move radially as `normalize(centroid − bboxCenter) · diagonal · factor · EXPLODE_MAX_SPAN (0.35)`; centered full-360 shells spread vertically in stable document order over `EXPLODE_CENTERED_SPAN (1.2) · diagonal · factor` (a single centered unit stays put). Grouping keeps every solid of an instance/body together. The widget applies offsets as mesh/edge-line `.position` transforms after every `buildModel` (transform only — reuse pool, geometry, and picking untouched; raycasts use world matrices; curve lines stay pinned at the origin). Factor 0 is assembled; the factor resets on reload/rebuild like measurements, and measurements stay world-anchored while displaced (hint reads `Explode N% — F to refit`).
- Selection and visibility: `fitView` frames the selected solid when `currentSelection.solidId` is set; `.` and double-click-on-solid also fit; `Tab` toggles sketch mode (guarded against pick modes, dialogs, text fields). `CadSelection.solidIds` multi-selects (Ctrl/Cmd in the outline, or a tree body/feature click mapping to all body solids); `solidId` stays primary (properties panel, fit). The outline's hide/isolate actions publish a hidden-solids set via `NukeCadStateManager.setHiddenSolidIds` — viewport state, never document state — applied in `applyShading` (faces and edges) and excluded from every picking path (`pickableMeshes()` / `pickableEdgeLines()`; three.js raycasts invisible objects, so the pool filters explicitly). Document curves hide exactly when every body consuming them as a sweep/pipe path is fully hidden (`curve-visibility.ts`, same `applyShading` funnel, `pickableCurveLines()`; unreferenced curves always stay). The set clears on `setModel` because positional solid indices can shuffle.
- Model Outline section layout contract: sections render as one list with 10 px gaps (`.outline-section`) and a 2 px header bottom margin. Every `.category-header` is the same 11 px uppercase treatment — `.category-header-label` (nowrap, ellipsis under pressure), 7 px gap, `letter-spacing: 0.3px`, muted color — while count badges and header buttons (`flex-shrink: 0`) never squeeze the label. Document rows share the 24 px grid (`document-settings-row`, 80 px label column + value column); `document-settings-subhead` (`DISPLAY`, `DESIGN PROPERTIES`) groups rows inside a section. Origin uses a `Show axes` master `NukeSwitch` row (aria-label `Show origin axes`, user-scoped `nukeCad.showOriginAxes`) above one compact chip row (`role="group"`, aria-label `Origin axes`): three equal-width 26 px `aria-pressed` chips in X/Y/Z order, each with a 12 px axis-colored line glyph and bold letter. Pressed chips tint their border/text with the viewport triad colors (`#e05252`/`#4caf50`/`#3b82f6`) over a 12% `color-mix` background; the master gates the whole triad and disables the chips (saved pressed state kept, muted at 0.45 opacity), while the per-axis chips apply whenever the master is on.
- Model Outline (`src/browser/widgets/outline-panel/`, `nuke-cad-outline-panel-widget`, "Model Outline"): read-only manifest volumes/surfaces list (plus ASSEMBLIES per-instance rows for assemblies) — no manifest editing UI. The header carries a muted body-count pill (`0 bodies` / `1 body` / `N bodies`) sourced from the open document's `bodies.length`, falling back to `result.solidCount` for script/STEP models. Picking syncs both ways through `NukeCadStateManager`: row click highlights the whole solid (Ctrl/Cmd toggles multi-selection, `outline-interactions.ts`); viewport picks select, scroll to, and expand the row. Hover actions **Hide** (toggle its solids) / **Isolate** (hide all others); a **Show all** header button appears while hidden; hidden rows render dimmed with an eye-closed marker. Opened via `nuke.cad.openOutlinePanel` (right shell) or the Nuke Tools sidebar (`CAD Studio → Geometry`). - Preferences (`src/browser/nuke-cad-preferences.ts`): `nukeCad.facetingTolerance` (default 0.001, exclusiveMinimum 0) is the export-quality default (script builds and builds with DAGMC/FEM export enabled; explicit per-call tolerance wins; applies to subsequent builds only; deliberately separate from openmc-studio's tolerance — nuke-cad cannot depend on openmc-studio).
