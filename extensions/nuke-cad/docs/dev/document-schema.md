# Document schema

The `.nuke-cad` JSON document (`src/common/cad-document.ts`) and its store, migrations, shell integration, and Export-Python codegen.

- Schema version is 3. Validate with `validateNukeCadDocument`; migrate with `migrateNukeCadDocument`. New migrations register steps in `MIGRATIONS` and bump `NUKE_CAD_SCHEMA_VERSION`.
- v2 introduced `bodies` plus boolean features; v3 adds top-level `curves`. The v1→v2 migration creates one implicit body per legacy feature; v2→v3 adds an empty `curves` array.
- `displayTolerance` is an optional positive number overriding the display-faceting tolerance for this document's viewport builds (export/FEM tolerances keep their own preferences). Absent uses `nukeCad.displayFacetingTolerance`; the tokamak example sets 0.015 so its cut-trimmed tessellation stays under the frontend read budget. `cloneDocument` copies it, so later mutations never drop it.
- `overlapCheck` is an optional boolean overlap-warning gate (absent = `true`). `false` suppresses cross-body and assembly-instance overlap warnings for a known-valid large assembly: `feature_builder` skips `_check_cross_body_overlap` and `assembly_builder` skips `_instance_overlap_warnings`, dropping the exact `O(n²)` boolean passes that dominate such builds (the validated 15-body/55-instance W7-X generator: 105 + 1485 booleans; 321 s → ~25 s). It is an author assertion about model validity, not a display setting — geometry, `selector_map`, and codegen are unchanged, and DAGMC export keeps its own overlap gate. `CadDocumentStore.setOverlapCheck(enabled)` commits once; enabling removes the field to keep the canonical absent-means-default form. Python structural validation (`_validate_document_refs`) rejects a non-boolean value.
- `views` is an additive v3 block (`SavedNamedView[]`, no migration — absent means none): `{id, name, position, target, up, createdAt}` stores a world-space camera pose with a unique id and unique trimmed name. `CadDocumentStore.addNamedView`/`removeNamedView` validate, cap the block at 32 entries, ride the normal undo/dirty path, and never schedule a rebuild. The geometry backend never reads it; Export Python and result-cache keys ignore it. See `viewport-outline.md`.
- `designStudy` is an optional additive v3 marker (no migration — absent means a normal document): `W7xDesignStudy = W7xCoilStudy | W7xCoilShapeStudy`. `w7x-coil-study` carries the measured 4/5/6-module count report (`moduleCount`, `valid`, `pitchDeg`, `moduleSpanDeg`, `uncoveredSectorDeg`, `moduleOverlapDeg`, optional `minCoilClearanceM`, `coilCoilOverlaps[]`, `coilShellOverlaps[]`, `summary`). `w7x-coil-shape-study` carries `{moduleCount: 5, coilCount: 50, bodyCount: 10, sectionWidthM, sectionHeightM, sectionTiltDeg, twistDeg, stations, referenceVolumeM3, summary}` for the native coil sweep layout. `validateNukeCadDocument` enforces kind-specific shapes. `CadDocumentStore.setDesignStudy(study | undefined)` commits once (no-op when unchanged, canonical-JSON comparison), rides undo/dirty, and `cloneDocument` preserves either kind. Display builds still work, but `geometry_service.build_document`, `build_document_partial`, and `build_assembly` return `success: false` when `designStudy` is present and `export_dagmc` or `export_mesh` is requested (`Design study document: simulation export is disabled. Use the valid 5-module W7-X generator for simulation-ready geometry.`); STEP export is not blocked.
- Every solid feature (`pad`/`pocket`/`revolve`/`groove`, `sweep`/`pipe`/`coilSweep` with a curve ref, `loft`/`helicalSweep`, `primitive` on a datum with optional `subtractive`, `multiTransform` over two pattern/mirror sources) targets a body id.
- `coilSweep` (additive v3) sweeps a rectangular section (`width`, `height`) along `pathCurveId`: optional `tiltDeg` (`-89..89`, default 0) rotates the section out of the tangent-normal plane, `twistDeg` rotates it progressively around the tangent, and `stations` (integer `8..720`, default 60) sets the loft resolution. It needs no sketch and is pattern/mirror eligible. The W7-X shape study uses ten of them for its native coil bodies.
- `import` features (additive v3, no migration) create body geometry from one STEP/IGES/BREP source. `ImportParams` carries `sourcePath` (document-relative POSIX path preferred), `sourceHash` (lowercase SHA-256), optional `sourceSize`/`sourceFormat`, optional `sourceUnit` (`mm`/`cm`/`m`) overriding the detected file unit, `selection` (`{mode: 'all'}` or `{mode: 'solids', solids: [{index, signature?}]}` with 1-based explorer indices plus faceCount/volume fingerprints), optional `placement` (intrinsic XYZ `rotateDegrees`, then `translate` in document units), and `maxSolids` (default 500). Source numbers scale to `document.units` (a unitless document keeps native numbers); the W7-X STEP declares millimetres but stores metre-scale numbers, so it sets `sourceUnit: 'm'` with `units: 'm'` and no scaling occurs.
- `sourceHash` is the import feature's build and cache identity: `sourceSize` is only an advisory freshness probe, mtime never keys anything, and changing the hash invalidates the feature plus dependents in both the in-session cache and the result-cache zip. `CadDocumentStore.addImportBodies` creates N bodies + N `import` features in one commit (one undo entry); `refreshImportSource` updates the hash/size of every feature sharing a path in one commit and the caller rebuilds. Export Python emits a runnable `_import_body` reader (hash/size verification, unit scaling, 1-based index/signature selection, optional placement) instead of a TODO.
- Boolean features (`booleanFuse`/`booleanCut`/`booleanCommon`) consume one target body plus one or more tool bodies, with optional `keepTools`. Bodies carry an optional `label` mapping to the region manifest / `selector_map` for DAGMC and mesh export.
- `BodyDef.appearance` is an optional display-only override `{color?: '#rrggbb', opacity?: 0..1}` (at least one field; absent = theme default). It rides the normal body record, so no migration or schema bump is needed. `CadDocumentStore.setBodyAppearance(id, appearance | undefined)` deep-copies the object, validates through `commit` (snapshot undo/redo, dirty flag, change event), rejects unknown ids and invalid values as structured errors, and never schedules a rebuild; `undefined` removes the override. The geometry backend, Export Python, and result-cache keys never read it. See `viewport-outline.md`.
- Features targeting a body consumed by a boolean are marked `stale` (uniform guard for dress-up, pattern/mirror/hole, and sketch-solid features).
- The store (`src/browser/document/cad-document-store.ts`) holds the active document, validates immutable updates, and tracks dirty state, sketch/feature/body selection, and per-feature build results. Sketch-local parameters merge into document parameters on sketch save. Destructive deletes that would orphan dependents are rejected.
- Undo is snapshot-based (pre-mutation documents, depth 100, redo cleared on new mutation, reset on load/create): `undo()` / `redo()` / `canUndo` / `canRedo` with normal dirty/validation/change effects, so rebuild scheduling observes them unchanged. Granularity is committed store mutations; sketch strokes reach the store only on save. Toolbar Undo/Redo plus `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` follow viewport key scoping and stay out of active sketch sessions.
- `.nuke-cad` files open in the CAD viewport by default (open-handler priority 500): parse JSON, load the store, run a viewport-only build (no DAGMC/FEM export). See `backend-pipeline.md` for the default export gates.
- Commands: `nuke.cad.newDocument`, `nuke.cad.saveDocument`, `nuke.cad.saveDocumentAs`, `nuke.cad.newSketch`, `nuke.cad.exitSketch`, `nuke.cad.openFeatureTree`. `newDocument` merges a `DOCUMENT_TEMPLATES` preset (`src/common/document-templates.ts`) over an empty v3 document. Save/Save-As enforce `.nuke-cad` via `ensureNukeCadExtension` (`cad-save-path.ts`). Named views add `nuke.cad.saveNamedView` (quick-input name prompt) plus `nuke.cad.restoreNamedView` / `nuke.cad.deleteNamedView` (view id argument, driven by the Model Outline rows).
- **Edit Parameters** reopens the feature-creation dialog prefilled for an existing feature and updates the document on confirmation.
- **Export Python** (`src/common/python-codegen.ts`) writes a deterministic, one-way, lossy build123d-ish starting point (never a round trip), saved via the Theia file dialog and `FileService`. Emission mirrors `feature_builder.py` / `sketch_builder.py`:
  - Arcs become `bd.CenterArc` with a signed degree sweep (document angles are radians); revolve uses `revolution_arc`.
  - Pattern counts include the original; full/partial circular sweeps step `360/count` resp. `angle/(count-1)`. Pattern/mirror instances transform a re-derived source solid (never the sketch; primitive sources re-derive the same way; multiTransform still hatches).
  - Boolean tools are combined before the operation. Contained sketch profiles (any nesting depth) are holes emitted with `bd.Mode.SUBTRACT`, matching backend outer/inner-wire pairing.
  - Ellipses become `bd.Ellipse(x_radius, y_radius, rotation=deg)` under `bd.Locations(center)`.
  - Loops containing a B-spline keep the authored control polygon as an explicit `bd.make_face([...])` edge list via the module-level `_bspline_edge` helper (raw OCP `Geom_BSplineCurve`), emitted once after imports whenever any non-construction B-spline exists — `bd.Spline` interpolates points and cannot express control-polygon curves. Periodic or non-unit-weight B-splines degrade the sketch to `# TODO(manual):`.
  - Curves are emitted as `bd.Spline` calls over sample points before the bodies/features blocks (sweep/pipe reference the curve vars).
  - Sweep/pipe emit `bd.sweep(...)` with the section repositioned to the path start via a `bd.Plane` from the curve start point and tangent (`fixedBinormal` adds a binormal-locked `# TODO(manual):` hatch); pipe sections are `bd.Circle(radius)` faces.
  - Loft emits `bd.loft([<section fn>()...], ruled=...)` in section order (an unbuildable section degrades the whole feature to `# TODO(manual):`).
  - HelicalSweep emits `bd.Helix(pitch, height=pitch*turns, radius, direction, lefthand)` plus the same `_sweep_plane` + `bd.sweep(...)` emission as sweep.
  - `import` emits `_import_body(...)` / `_place_import(...)` helpers: the source path resolves relative to the script, SHA-256/size are verified, STEP/IGES/BREP solids are read once per configuration, the source-unit override scales to document units, and the authored 1-based index + faceCount/volume picks are verified (unique signature repair included). No imported body is a TODO.
  - A grounded assembly always emits the `_mate_place` helper (even with no mates) and the script ends with a top-level `model` compound: placed instance variables for assemblies, otherwise the non-`None` body variables. The exported script can therefore run directly in the script pipeline.
  - Face datums, external geometry, fillet/chamfer edges, draft/shell faces, and hole placement emit as `# TODO(manual):` comments, never silently dropped.
