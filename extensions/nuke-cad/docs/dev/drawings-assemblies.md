# Drawings and assemblies

3D curves with expressions/units, drawing sheets with HLR projection, and the assembly/mate/BOM/fastener stack.

- 3D curves are lightweight polylines in the top-level `curves` array. Each curve has `id`, `name`, `source` recipe, and `samples` (`[x, y, z]` points). Sources: `points` (explicit samples), `parametric` (expressions for `x(t)`, `y(t)`, `z(t)` sampled uniformly over `[tStart, tEnd]`), `fourier` (cos/sin coefficients sampled over `[0, 2π)`).
- The expression mini-language lives in `src/common/expression.ts`, with a units layer (`Quantity`, per-operator unit rules, coercion) active wherever a document declares `units` (`mm`/`cm`/`m`; absent = legacy unitless, and the unitless sampler path rejects unit syntax rather than folding it). The store resamples parametric and Fourier curves on add/edit, coercing each coordinate to the declared unit; dimension labels carry the unit suffix. The toolbar units dropdown writes `document.units` through a `setUnits` mutation (tag-only — existing numbers are never rescaled). Closed curves repeat the first sample exactly at the end (Fourier always; parametric when the expressions meet at both ends) so the backend proximity check marks the wire closed.
- Curves render as viewport line segments, list under the Feature Tree **CURVES** section, and export to Python as `bd.Spline` calls (see `document-schema.md`). The sweep/pipe dialogs pick the path curve from a dropdown or a viewport curve-pick mode (click-through banner, hover highlight, right-click/Escape cancel; `resolveCurvePick` guards deleted curves). Curve visibility follows body hiding (see `viewport-outline.md`).
- The Python backend (`python/curve_builder.py`) fits B-spline wires: `points` sources approximate with a tolerance derived from sample spacing, parametric/Fourier sources interpolate; closed curves detected from first/last-sample proximity relative to average spacing build as periodic wires.
- Drawings are an additive `drawings: DrawingSheet[]` block (v3, no migration, never cached in the zip). `python/drawing_service.py` projects exact B-rep linework with OCP `HLRBRep_Algo`/`HLRToShape` (never faceted approximations), cuts section views with a half-space box, and emits SVG natively plus DXF via optional `ezdxf` (PDF deferred — no PDF writer in the env). Dimensions reference model `TopologyRef` fingerprints and recompute from 3D on every build (`stale: true` + last-good text on broken refs).
- Frontend: the **Drawing Sheet** workspace (`nuke-cad-drawing-widget`, `nuke.cad.openDrawingSheet`) renders 2D SVG with drag-to-place (5mm snap) and drives the `buildDrawing` RPC on the shared backend interface; dirty drawing state never triggers a full rebuild. The widget is a full drafting layout: grouped toolbar (sheet/view/dimension/output, zoom, grid/snap/frame toggles), framed paper with a title block, dot-grid canvas, right inspector (sheet, selected view scale/hidden/delete, view list, dimension list), and a status bar. With no open document it renders a framed "No CAD document open" card (numbered workflow primer) on the dot-grid canvas; the sheet-start card shares the same surface. Zoom uses the SVG `getScreenCTM()` inverse for pointer mapping; middle-drag pans. `fitSelectedView` scales the selected view from its projected bounds and snaps to standard scales. Drawing mutations auto-save the shared document (the store URI is a file URI; `documentFilePath()` converts it to `fsPath`) before the HLR process spawns, so `buildDrawing` never sees a stale file or a `file://` cwd. New store mutations: `updateView` (scale/showHidden), `deleteView` (cascades child views/dimensions), `deleteDimension`, and `deleteSheet`. Dimensions are created by picking model edges in the 3D viewport (edge-picker broker → `addDimension`). Face-on HLR views legitimately show 4 visible + 4 hidden box edges (depth edges degenerate) — only off-axis views show all 12.
- Assemblies build on the mate-connector foundation (`src/common/assembly-document.ts` + `assembly-placement.ts`, frozen spec): instances with placement overrides, connectors as named frames, one mate per part pair, explicit grounded instance, closed-form placement (`R = Ra·Rbᵀ`) and per-mate-type DOF counting.
- `python/assembly_builder.py` resolves parts (same-doc body → `.nuke-cad` path → STEP/IGES/BREP file), solves placements BFS from ground (computed at build, never written back), and `build_assembly()` reuses `_process_shape` with `<instanceId>/<bodyLabel>` selectors. The external W7-X samples download or copy their MIT-licensed STEP into `<document-stem>.parts/` and store a relative part path, so the saved project folder is self-contained. `build_document()` and `build_document_partial()` (`--from-document`, the viewport path; the partial cache cannot address placed instances) delegate to `build_assembly()` when the document carries a grounded assembly, so assembly documents render on import, reopen, and edit; absent/ungrounded assembly stays single-part. STEP export uses an OCAF product structure; DAGMC reuses the imprint path with overlap as a warning. The schema carries one additive optional `assembly` field (v3, absent = single-part, byte-identical).
- `CadDocumentStore.addAssemblyInstances` appends N instances and optionally sets the grounded id in one commit (one undo entry), keeps caller-supplied stable ids such as `coil_01_m0` when unique, generates ids otherwise, and validates every placement against the frozen assembly spec even while the section is ungrounded. `body:<id>` instances reuse a single own-body build of the document (including `import` features) and emit `<instanceId>/<bodyLabel>` selectors, so many placed instances share one source B-rep.
- The W7-X generator is the batch case: 15 imported bodies (10 coil shapes + 5 full-360 shells) placed as 55 instances (50 coils = 10 shapes × 5 modules + 5 shells) with no 50-way pattern/fuse path. It sets `units: 'm'`, `displayTolerance: 0.1`, and `overlapCheck: false` for the validated layout, grounding `coil_01_m0`. Validation is 1-based index + face count + volume; STEP product names are advisory only, because OCCT reports the assembly root product name for every solid. The valid generator is five-module only; `src/common/w7x-study.ts` adds a separate 4/5/6-module design-study plan (40/50/60 coils, `designStudy` report) whose documents reject simulation export.
- The native shape study (`src/common/w7x-shape-study.ts`) is the editable counterpart: ten `coilSweep` bodies from the committed `w7x_coils.json` centerlines, placed across five modules (50 instances) with no external STEP. Defaults are 0.37 m square section, 8.6° tilt, 60 stations; the total volume is ~0.55% above the imported reference, and the `w7x-coil-shape-study` marker keeps display-only. Editing a coil body updates all five module instances.
- The viewport renders per-instance `THREE.Group`s sharing source-face BufferGeometry (reuse key `<sourcePath>#<bodyId>::<faceFingerprint>`); the mate dialog + connector pick mode mirror the dress-up pattern; the store never grounds implicitly, but the one-click CAD import explicitly grounds its first instance so the assembly builds. The **BOM** panel (`nuke-cad-bom-panel-widget`, `nuke.cad.openBomPanel`) lists instance/source/mate/DOF rows with viewport selection sync; outline and tree carry assembly sections (the read-only rule stands).
- `python/fastener_data.py` holds versioned ISO/UNC thread tables consumed by modeled-hole threading (pitch/tap by diameter) and later hole recognition.
